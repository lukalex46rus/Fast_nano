## 1. Критерии готовности модуля (Definition of Done)

Модуль считается готовым, когда выполнены ВСЕ пункты:

| № | Критерий | Проверка |
|---|---|---|
| 1 | Шапка: НАЗНАЧЕНИЕ / API / ОГРАНИЧЕНИЯ / СТОИМОСТЬ / ПРИМЕР / ЗАВИСИМОСТИ | REVIEW |
| 2 | Заявлены все занимаемые ресурсы (FN_CLAIM_* / acquire) | SA + RESOURCES.md |
| 3 | Известен sizeof каждого объекта и объём статических данных | RESOURCES.md §2 |
| 4 | Нет таблиц в RAM, нет 64-бит/float в горячих путях | GREP INV-01/03 |
| 5 | Многоисходные операции возвращают Result, границы проверены | GREP INV-21 + HOST |
| 6 | Нет бесконечных ожиданий железа; таймауты через expired() | GREP INV-13 |
| 7 | Подбор делителя не превышает запрошенную частоту | HOST INV-14 |
| 8 | Проверено на железе или численно (CRC — контрольные значения) | HW / HOST |
| 9 | Контракт заполнен в CONTRACTS.md, инварианты соблюдены | REVIEW |
| 10 | Внесён в MODULES.md (статус ✅) и DECISIONS.md (если меняет решение) | REVIEW |

## 2. Регламент изменений (гейт «код + док в одном коммите»)

| Изменение | Обязательный обновляемый док |
|---|---|
| Публичный API (сигнатура/семантика) | CONTRACTS.md (контракт модуля) |
| Занимаемый ресурс (вектор/таймер/пин) | RESOURCES.md §3–6 + MODULES.md |
| sizeof / бюджет / WCET | RESOURCES.md §2/§7 |
| Новое правило / инвариант | INVARIANTS.md |
| Архитектурное решение / альтернатива | DECISIONS.md (ADR) |
| Зависимость между модулями | ARCHITECTURE.md §4/§5 + MODULES.md |
| Состав/статус модуля | MODULES.md |
| Порядок работ / открытый вопрос / расхождение | ROADMAP.md |

Правило: коммит, меняющий код, ОБЯЗАН менять владеющий док в том же коммите. Иначе — отклонить.
Каждый факт живёт в одном файле; остальные ссылаются (карта владения — ROADMAP.md).

## 3. Чек-лист самопроверки перед коммитом

- [ ] Дефолтный скетч собирается (Fast_nano_core.h + целевые модули).
- [ ] Линтер инвариантов (§4) проходит без новых нарушений.
- [ ] Нет новых таблиц в RAM / float / 64-бит в hot path.
- [ ] Все новые публичные операции возвращают Result и проверяют аргументы.
- [ ] Нет while без таймаута; делитель не превышает запрос.
- [ ] sizeof новых объектов внесён в RESOURCES.md.
- [ ] Контракт нового/изменённого API заполнен.
- [ ] avr-size: .data/.bss/flash не выросли сверх бюджета (или рост обоснован в DECISIONS.md).
- [ ] Затронутые D-решения обновлены/добавлены.
- [ ] Статус модуля в MODULES.md актуален.

## 4. Линтер инвариантов (этап 4.1 ROADMAP)

Скрипт (host, grep/regex по src/) + скрипт графа #include. Порог: 0 новых нарушений.

| Проверка | Паттерн / метод | Инвариант |
|---|---|---|
| Таблицы в RAM | `(const\|constexpr).*\[\s*\d*\s*\]\s*=` без PROGMEM/FN_PROGMEM/PSTR | INV-01 |
| float/64 в hot path | `\b(float\|double\|u?int64_t\|long long)\b` в bus/pin/timer .cpp, Registers.h | INV-03 |
| ISR в шапке | `\bISR\s*\(` в *.h (не комментарий) | INV-06 |
| Флаги вне центра | `#define F_USE_` вне Features.h/Config.h | INV-09 |
| Имена-макросы Arduino | объявления bit/bitRead/min/max/swap/byte/word | INV-10 |
| _Заглавная | `\b_[A-Z]` в объявлениях | INV-11 |
| while без таймаута | `while\s*\(` без expired/timeout в теле | INV-13 |
| Прямое сравнение времени | `(millis\|micros)\s*\(\s*\)\s*[<>]` | INV-20 |
| Свой Result-enum | `enum.*\{[^}]*Ok[^}]*Timeout` | INV-21 |
| Дубли определений | повторяющиеся struct/трейт в разных шапках | INV-22 |
| Граф зависимостей | парсинг #include → топсорт, циклы, направление вниз | DEP-1/2 |
| Самодостаточность include | символ используется, но объявляющий заголовок не в транзитивном замыкании | INV-23 |
| Дубли имён в namespace | одно имя объявлено дважды в одном namespace (разные типы) | INV-22 |

SA-проверки (static_assert) компилятором: INV-05 (FN_CLAIM_VECTOR), INV-18 (частично), INV-22.

## 5. Верификация по типам

| Тип | Что покрывает | Инструмент |
|---|---|---|
| HOST unit | CRC, bits, RingBuffer, квадратура, FixedPoint, Mapping, wrap времени, кламп | gcc на ПК, -fsyntax-only + тесты |
| HW | регистры/glitch, тайминги, ISR-гонки, шины, сон, Front open-drain | Nano + осциллограф/логический анализатор |
| STATIC | инварианты, граф зависимостей, sizeof | линтер §4, static_assert |
| RESOURCE | регресс SRAM/flash/stack | avr-size, avr-objdump, stackPaint |

Правило: чистая логика тестируется на хосте (без AVR); регистры/тайминги — только на железе.
Контрольные значения CRC обязательны (критерий 8).

## 6. Порядок работ над модулем (внутри слоя)

аудит → контракт (CONTRACTS.md) → код → проверка (HOST/HW/STATIC) → запись (MODULES/DECISIONS/RESOURCES).
Слой готов → следующий. Нижние слои первыми (L0→L10). Зачаточные слои за гейтом F_USE_* (DEP-9).
