# INVARIANTS.md — глобальные инварианты Fast_nano

**Версия:** 1.0 · **Дата:** 17.11.2026
**Статус:** перенос жёстких правил R1–R19 + D25 в проверяемую форму.
**Границы:** здесь живут ТОЛЬКО системные инварианты и способ их проверки.
Контракты API → CONTRACTS.md; бюджеты/sizeof → RESOURCES.md; история решений → DECISIONS.md.

Инвариант = утверждение, истинное для ВСЕЙ системы всегда. Нарушение = баг, не стиль.
Каждый инвариант имеет ID, формулировку, способ проверки и ссылку на решение (D*).
Проверки: SA = static_assert, GREP = линтер (этап 4.1), HOST = host-test, HW = железо,
REVIEW = самопроверка по чек-листу PROCESS.md.

---

## Группа A. Память и данные

### INV-01 (R1, D11). Таблицы только в PROGMEM
Утверждение: любые константные таблицы/массивы размещаются во flash (PROGMEM) и
централизованы в Tables.cpp; `const` без PROGMEM на AVR = .data = SRAM.
Проверка: GREP `(const|constexpr).*\[\s*\d*\s*\]\s*=` без PROGMEM/FN_PROGMEM/PSTR;
HW: avr-size .data до/после.
Известные нарушения: bus/Spi.cpp kDivs[7], timer/Timer2.cpp kClocks[7],
timer/TimerCommon.h kClocks[5] → backlog G-2.

### INV-02 (R2, D2). Строки диагностики только через PSTR/FN_PSTR
Утверждение: строки ассертов/диагностики во flash; __FILE__ — полный путь, десятки байт SRAM.
Проверка: GREP строковых литералов в вызовах crash/assert без PSTR; REVIEW.

### INV-03 (R3, D76). Нет 64-битной арифметики и float в горячих путях
Утверждение: в ISR, побайтовых циклах шин, pin-операциях нет float/double и int64/uint64.
__udivdi3 ≈ 400 Б, soft-float ≈ 600 Б flash. В math/float-варианты допустимы (не hot path).
Проверка: GREP `\b(float|double|u?int64_t|long long)\b` в hot-path файлах (bus/*.cpp,
pin/*.cpp, timer/*.cpp, core/Registers.h); REVIEW для math.

### INV-04 (R4). Внутренние циклы по указателям
Утверждение: побайтовые обходы — инкремент указателя, не 16-битный индекс (индексная
арифметика дороже на AVR).
Проверка: REVIEW; objdump при регрессе таймингов.

### INV-18 (R18, D34/D77). Проверка диапазона приёмника перед сужением
Утверждение: перед сужающей записью проверяется диапазон приёмника; uint8_t(256)=0
(100% скважности превращалось в 0%).
Проверка: SA где возможно; HOST (кламп скважности, Any narrowing); REVIEW.

## Группа B. Конкурентность и прерывания

### INV-05 (R5). Один вектор = один владелец
Утверждение: каждый ISR-вектор имеет ровно одного владельца; заявка через FN_CLAIM_VECTOR.
Два ISR = multiple definition of __vector_N.
Проверка: SA (FN_CLAIM_VECTOR); линк (отсутствие дублей). Модель владения → RESOURCES.md.

### INV-06 (R6). Все ISR живут в .cpp
Утверждение: ISR никогда не определяются в заголовке (umbrella из двух TU даст дубликаты).
Проверка: GREP `\bISR\s*\(` в *.h (исключая комментарии).

### INV-07 (R7, D79). Многобайтовые разделяемые данные / RMW — под AtomicBlock
Утверждение: чтение/запись uint16/uint32 разделяемых данных и любой read-modify-write
защищены AtomicBlock; старший байт идёт через TEMP, ISR между байтами портит.
8-битный одиночный доступ атомарен аппаратно (без cli).
Проверка: REVIEW; HOST (AtomicCounter); HW (гонки ISR/main).

### INV-13 (R13, D25). Нет бесконечных ожиданий железа
Утверждение: ожидание готовности железа только через fn::expired()/expiredUs() с таймаутом;
счётчик итераций зависит от -O/версии GCC; при неинициализированной периферии флаг не выставится.
Проверка: GREP `while\s*\(` без expired/timeout в теле; REVIEW.

### INV-17 (R17). RAII без глобального побочного эффекта в деструкторе
Утверждение: деструктор RAII-объекта не гасит шину/ресурс глобально (TransferGuard/I2cScope
гасили шину из локального объекта). Освобождение — явный end()/release().
Проверка: REVIEW деструкторов.

### INV-20 (D25). Сравнения времени через elapsed/expired
Утверждение: wrap millis через 49.7 суток, micros через 71.6 мин; прямое `millis() > deadline`
ломается на переполнении. Только elapsed()/expired()/expiredUs().
Проверка: GREP `(millis|micros)\s*\(\s*\)\s*[<>]`; HOST (wrap-тест).

## Группа C. Аппаратные последовательности

### INV-08 (R8). Порядок настройки вывода: PORT → DDR
Утверждение: сначала PORT, потом DDR; иначе glitch (HIGH после INPUT_PULLUP→OUTPUT).
Проверка: REVIEW regs::modeImpl; HW (осциллограф).

### INV-14 (R14, D42). Делитель — максимальная частота, НЕ превышающая запрос
Утверждение: подбор делителя не разгоняет шину выше запрошенной частоты (округление вверх
разгоняло SPI в 4.17 раза). Для таймеров погрешность ≤1 тик документируется отдельно.
Проверка: HOST (calcDiv/calcClock/bestClock по граничным частотам); HW.

### INV-15 (R15, D18/D45). Коды режимов/делителей из даташита
Утверждение: значения берутся из даташита, не из порядкового enum (set_sleep_mode(uint8_t(enum))
давал ADC вместо PowerDown; CS2x ≠ CS0x).
Проверка: REVIEW против даташита; HOST (periodTicks, prescaleOf).

### INV-16 (R16, D41). Open-drain: «высокий» = input без подтяжки
Утверждение: отпускание линии = DDR=0 без подтяжки, не PORT|=mask (подтяжка 30–50 кОм даёт
фронт в мкс; на 400 кГц связи нет).
Проверка: REVIEW I2cSoft/recover; HW (фронт SCL/SDA).

### INV-19 (R19, D49/D62). Регистровый драйвер не заявляет владение устройством
Утверждение: владение заявляет потребитель, не регистровый драйвер (Timer1::takeover с
FN_CLAIM_TIMER запрещал всех потребителей сразу). Разделяемый ресурс — runtime acquire.
Проверка: REVIEW; модель владения → RESOURCES.md. Устраняет двойственность P0-2/P0-4.

## Группа D. Сборка и именование

### INV-09 (R9). Гейт внутри модуля, флаги централизованно
Утверждение: #if F_USE_X внутри модуля; per-TU переопределение = нарушение ODR (компилятор молчит).
Проверка: GREP `#define F_USE_` вне Features.h/Config.h; REVIEW.

### INV-10 (R10). Имена не совпадают с макросами Arduino
Утверждение: не использовать bit/bitRead/min/max/swap/byte/word как идентификаторы
(препроцессор не знает namespace).
Проверка: GREP объявлений с этими именами; компиляция с Arduino.h.
Известные нарушения (закрыты P0-12…P0-15): Pin::bit→bitIndex, Crc::Engine::byte→step,
fn::math::abs→absVal, GraphicsDisplay::swap→swapValues.

### INV-11 (R11). Нет идентификаторов _Заглавная
Утверждение: имена вида _X зарезервированы стандартом во всех областях.
Проверка: GREP `\b_[A-Z]` в объявлениях.

### INV-12 (R12). Проверки границ и nullptr обязательны
Утверждение: публичные операции проверяют аргументы (FN_BITS_CHECKS, Result::BadArg/OutOfRange).
Проверка: REVIEW; HOST (граничные аргументы).

### INV-21 (новый). Единый тип результата
Утверждение: многоисходные операции возвращают fn::Result; bool только для бинарного исхода;
свой enum с Ok/Timeout/Busy запрещён.
Проверка: GREP `enum.*\{[^}]*Ok[^}]*Timeout`; REVIEW.

### INV-22 (новый, из P0-1). Одно определение сущности
Утверждение: каждая сущность (тип/трейт/функция) определена ровно один раз; дублирование
между шапками = redefinition/ODR.
Проверка: компиляция; GREP дублей определений (AlwaysFalse Compiler.h↔Types.h).
Известные нарушения (закрыты): AlwaysFalse Compiler.h↔Types.h (P0-1),
pulse_detail::last как uint32_t и Result (P0-23).

### INV-23 (новый). Заголовок самодостаточен
Утверждение: каждый заголовок включает всё, что использует сам; порядок include
в .cpp не должен влиять на компиляцию. Транзитивные зависимости не считаются —
если модуль вызывает regs::, он включает Registers.h явно.
Проверка: GREP+граф (символ ↔ объявляющий заголовок в замыкании); компиляция .cpp
с первым include = Config.h.
Известные нарушения (закрыты P0-21/P0-22): Config.h без stddef.h, I2c.cpp без Registers.h.
